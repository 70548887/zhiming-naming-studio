## 本轮已实施：读得清楚、状态明确、修改可保留

### 本轮联验重点

- 从已有方案开始，只修改候选审阅或字形选择，分别尝试关闭详情、保留某字另起一组、刷新或关闭窗口，检查保护入口是否完整。
- 修改报告意见后，分别打开其他方案、生成新候选、保存以及恢复历史，检查草稿与保存状态是否一致。
- 删除当前客户、恢复备份成功后，当前页面必须清除已失效的档案与方案；不能继续编辑或保存旧内存记录。
- 用键盘完成录入、修错、打开详情、保存、比较和关闭弹窗；同时检查中文输入法组合输入期间的 Esc 行为。
- 在三档桌面宽度下检查长父母姓名、复姓、长寓意、较长来源记录和错误消息；局部表格需要横向滚动时，应只滚动表格区域。

## 完成口径

每批以“页面可完成主要任务、修改不会意外丢失、保存状态与实际数据一致、键盘可用、三档桌面宽度可读”为共同验收标准。浏览器联验、桌面安装运行、PDF 版式与跨机验收分别记录结果，不互相替代。

显示偏好一项已于1.0.7提前实现：配置只包含密度和字号；读取损坏时使用默认显示，保存失败提示仅当前窗口生效，不影响客户库或PDF字号。

## 1.0.28 原句局部旺势与输入完整性分开

任注1.4作为需明确选择的独立方法，展示木方、火方两项局部旺势。每项区分充分路径状态与局部能力结论，列原句条件、实际源支／同气日干字位和来源；完整性标作输入事实，不作为正判门槛。缺时但年、月、日已齐木方且日干同气时，仍显示原句支持；真太阳时日干尚未确定时保持待核，不以代表时刻补日主。

单项事实标题与整条路径使用不同状态文案：输入完整性显示“四柱已定／存在未定柱”，并注明不作为证明前提；来源谓词显示“该项前提符合／不符／待核”。不把一个未知元数据标题写成“本证明仍缺条件”，避免它与已经成立的局部证明相互误导。

月份、第四支及明干不设任意白名单，冲克、合会、重复支、藏干和根节点完整保留。页面与PDF须明确局部旺势不等于净胜负、所有根有效或完整从强／喜用，不使用“已成功定格”“已解四害”等字样，也不改变姓名评分排序。原文作者层使用可读标签；来源节录与原句定位保留，不把内部枚举充作产品解释。

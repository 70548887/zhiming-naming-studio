审计日期：2026-10-18。当前 `package.json` 和已交付安装包版本均为 **1.0.8**。本轮检查现有代码、规则资料、备份与审阅流程、实际浏览器键盘操作，并使用独立目录复现问题，没有写入正常客户库。本轮没有修复下列问题，也没有重新发布安装包。

结论：**确认 5 项待修复问题；规则、资料覆盖、使用引导和外部验收仍有缺口。现有 256 项测试全部通过，并不覆盖本轮新发现的全部路径。**

后续状态：A01–A05已在1.0.9完成修复，307项回归、当前Windows独立安装及37页PDF验证通过，见 `RELEASE-1.0.9.md`。下文保留审计时的原始复现与待完善范围。

## 一、已复现问题，按修复优先级排序

### A01 · P1 · 八字快照未按出生资料核验，错误分析可从备份进入报告

- 位置：`src/main/store.ts:29–35`，恢复入口 `:140`。
- 当前行为：`validAnalysis` 对八字五行、系统喜用和年/月柱缺少完整的出生资料绑定；当前奇门验证路径已经核对日柱和时柱，不能将此问题泛化为全部四柱都不校验。
- 隔离复现：从正常生成的方案备份开始，只把 `analysis.bazi.elements.木` 改为 `999`，其余不动。`validSession` 返回 true，`restore` 成功，HTML 报告的五行分布采用 `木 999`。单独修改喜用、强弱文本或年柱天干也通过恢复校验；日柱天干的负面对照会被现有奇门校验拒绝。
- 影响：错误或被改写的备份可以显示与出生记录不一致的出生分析；后续保存审阅会沿用这些已存分析。正常 UI 不提供这些字段的直接编辑，本次没有发现真实客户数据已发生此问题。
- 建议：按保存的算法版本和出生资料重建确定性八字字段，校验四柱、五行计数、系统喜用、原始依据和版本；人工喜用仍单独保存。旧规则应使用对应验证器，不能直接拿新规则改写历史。
- 验收：错误数值、日柱、喜用、原始依据分别篡改均拒绝；正常历史、未知时刻及交节边界可恢复；拒绝后当前库字节不变。

### A02 · P2 · 备份恢复接受不存在的夏令时民用时刻

- 位置：`src/main/store.ts:21–26`、`:139`；正常保存对照为 `src/main/service.ts:35`。
- 隔离复现：`2024-03-10 02:30 / America/New_York` 在夏令时跳转中不存在。正常 `saveProfile` 拒绝；把只含档案的合法 SQLite 备份中出生资料改成该时刻后，恢复成功，恢复后的档案再次分析报错。
- 原因：恢复只验证日期、钟面格式和 IANA 时区名称，没有验证该本地时刻能否映射到实际瞬间。
- 建议：抽出共享出生资料验证，正常保存、恢复和导入复用；保留重复时刻的现有取法及提示。
- 验收：DST 缺口拒绝、重复时刻按既定规则处理；农历、时刻未知和历史时区正常资料仍通过。

### A03 · P2 · 双客户端旧方案保存会静默覆盖新审阅

- 位置：`src/main/service.ts:57–74`，特别是 `:70`。
- 隔离复现：A、B 各持有同一方案的旧副本。A 保存候选审阅，B 仅修改总体方案意见后提交整份旧副本，A 的候选审阅被恢复为空；A 的内容仍能在审阅历史找到。
- 影响范围：浏览器两个标签页或多个客户端持有同一方案时可触发。原生应用的单实例、单主窗口和前端忙状态降低常规触发概率。现有客户库文件锁阻止同时写坏文件，但不识别过期的业务快照。
- 建议：给方案增加审阅修订号，保存使用 compare-and-swap；或改为带预期版本的字段级审阅补丁。冲突时保留当前草稿并让用户选择重新载入或合并。
- 验收：A、B 不同字段不被静默回退；相同字段冲突有明确反馈；数理确认、收藏、历史恢复纳入同一修订约束。

### A04 · P2 · 更新知识包后，历史方案缺少与原数据版本对应的来源清单

- 位置：`src/main/service.ts:18`、`:54`，`src/main/store.ts:166`，`src/shared/types.ts` 的 `NamingSession`。
- 隔离复现：先生成含 `shijing-161-3` 引文的方案，再导入结构合法、但修改 `shijing` 来源 URL 和 commit 的知识包。旧方案的 `dataVersion` 保留，`bootstrap.sources` 却只返回新来源；方案未携带原来源清单。
- 影响：**原引文正文仍保留**，缺口是无法在应用里按历史数据版本查回当时来源详情。随包原来源可手工查 source-lock，但自定义包连续更新后，单份 `knowledge.previous.sqlite` 无法保存所有历史版本。
- 建议：生成方案时保存实际引用来源的不可变快照，或按完整数据版本归档来源 manifest；备份、报告和审阅历史使用同一来源记录。
- 验收：更新两次知识包再恢复客户备份，旧方案仍展示生成时的来源、commit 和哈希；当前知识库展示新来源，两者可区分。

### A05 · P2 · 品牌 Logo 上传无法通过键盘进入

- 位置：`src/renderer/main.tsx:187`、`src/renderer/styles.css` 中 `.upload-label input`。
- 实际浏览器复现：在独立预览 `5181` 的设置页，从“报告联系方式”按 Tab，焦点直接进入“保存品牌”，跳过“选择图片”。DOM 确认上传 input 为 `display:none`、无可见矩形，外层 label 的 `tabIndex=-1`、没有按钮角色。
- 建议：使用可聚焦的真实按钮打开文件选择器，或保留可访问的原生文件输入；提供清晰的焦点样式和文件格式说明。
- 验收：仅用 Tab、Enter/Space 完成选择图片、取消、重新选择和移除；鼠标上传及读取失败后的草稿保留仍正常。

## 三、传统规则仍未完成的部分

1. **八字**：当前仍为固定藏干权重、月支×2及38%/55%阈值的扶抑启发式；季节建议是粗略寒暖意象。月令分日司权、按流派分开的扶抑/调候意见、从格、化气与合化的支持/反对/缺失证据尚未启用。不能把当前输出当作完整喜用神体系。
2. **藏干来源口径**：当前引擎的巳藏干顺序为丙/戊/庚，所用历法库和本轮候选资料为丙/庚/戊；当前权重使顺序有实际影响。需先固定采用的来源与口径、准备分歧例子，再决定是否修改并升级算法版本；本轮没有将任一种顺序认定为唯一正确。
3. **奇门**：已有时旬空、时驿马及七项结构检查；十干全范围入墓、真假空、四害解除、姓名落宫和验名仍未实现。现有界面与文档有明确边界说明。
4. **五格三才**：已支持限定的单/复姓、单/双名与有源字形确认；三才目前为五行关系，当前规格有意未纳入125种判表，熊崎原典未校勘。数理超81不循环解释。后续若扩展这些范围，需另定规则和验收。
5. **真太阳时**：尚未实现可选经纬度、均时差算法及其独立边界例；当前使用民用出生记录，原始日期时刻应继续保留。

源码已有 `bazi-evidence.ts`、`BaziEvidenceView.tsx` 等未接线在制文件和可选类型。实际生成引擎、来源锁、保存恢复、报告、独立例盘与安装验收尚未完成接线，**不计为1.0.9已交付功能**。未审定研究原件已留在 `.local/bazi-109/research/`，没有作为启用规则打包。

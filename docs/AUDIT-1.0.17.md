# 1.0.17 新增审计：草稿替换与备份降级边界

审计日期：2026-10-18。以下仅记录本轮新增的4项原始复现；此前已经修复的设置异步保存、候选事实归档、固定来源元信息篡改等问题不重复列入。本轮复现使用隔离React处理器或独立临时客户库，未读取正常客户资料。1.0.17已有测试、安装和PDF通过记录继续有效，但未覆盖下面这些路径。4项已在1.0.18修复，95文件719测试、类型检查、构建及候选安装／界面／报告验证通过；原生关闭新版复验中断，最终包仅继续命令行与静态校对，不能称全部验收完成。下文保留审计时的原始行为。

## A01 · P2 · 恢复备份会替换未保存的AI、密钥和品牌草稿

- 审计时路径：`src/renderer/main.tsx` 的恢复回调、`refresh(true)`／设置重置及替换保护；位置见当时记录 `:86`、`:94`、`:212`。修复中行号可能变化。
- 触发：只编辑模型名称、API密钥草稿和工作室品牌，不修改客户或审阅；点击恢复备份并同意已有的“替换已存数据”确认。
- 复现：模型由 `pending-unsaved-model` 回到 `old-model`，密钥草稿从存在变为空，品牌回到原工作室；没有出现专门的未保存设置选择，关闭脏状态也随之清除。
- 范围：这是执行当前App回调、替身恢复／bootstrap服务的隔离复现；未操作原生文件选择器。已有范围确认涉及已保存数据，并说明本机AI保留，但没有指出AI草稿也会丢失。没有证明已保存凭据或正常客户库被删除。
- 修复要求：恢复前明确保护会被替换的设置／密钥／品牌草稿；继续编辑保留草稿。后续取消文件选择或恢复失败时，已有文字草稿仍保留；确认成功后才重新读取结果。
- 证据：`.local/close-118/dirty-chain-results.json` 的 `restore-settings-draft`；复现入口 `node .local/close-118/dirty-chain-repro.mjs`。

## A02 · P3 · Logo读取等待期没有纳入关闭保护

- 审计时路径：`src/renderer/main.tsx:92` 的图片读取与 `:98` 的 `beforeunload` 脏状态。
- 触发：选择有效品牌图片，在FileReader仍等待期间关闭窗口或刷新。
- 复现：`logoReading=true`、保存品牌按钮禁用，但 `beforeunload=false`；只有读取完成、品牌字段实际变脏后才启用关闭保护。
- 范围：隔离处理器刻意延迟FileReader以验证状态链，未测原生文件选择／实际图片读取的耗时；影响是尚未完成加载的图片选择，不是已经保存的客户数据。
- 修复要求：读取等待本身也作为未完成修改保护，明确显示读取中；放弃恢复时取消旧读取，失败或取消路径不能把晚到图片写回新状态。
- 证据：同文件的 `pending-logo-read`。不能用普通已加载品牌草稿的关闭提示通过替代此等待期验收。

## A03 · P2 · 删除整份来源快照可让现代备份跳过固定来源核对

- 审计时路径：`src/shared/session-sources.ts:67–68` 对缺省清单的旧记录兼容，以及 `src/main/store.ts` 的方案／恢复校验、各固定来源验证器的缺省早返。
- 触发：从正常生成的八字1.7、奇门1.3方案备份中，只删除整个 `sourceSnapshot`，保留新计算证据与完整知识包。
- 复现：`validSession=true`，恢复被接受，来源状态变成 `missing`，客户库确实被替换。对照：只删从杀单条来源、伪造从杀来源commit或缺少知识包时，已有校验会拒绝，当前库字节不变。
- 范围：这是修改外部备份后的恢复一致性绕过。正常生成会创建清单，普通审阅保存保留原清单；没有证明正常生成会自行遗漏来源。它也不同于此前已修的“同ID修改URL／commit／哈希”路径。
- 修复要求：现代已发布版本必须携带生成时清单，不能通过删整份清单冒充旧资料；真正历史版本的缺失状态按其明确版本合同保留，不以当前来源补造。
- 证据：`.local/close-118/engine-backup-probe-result.json` 的 `current-without-source-manifest` 及3个对照项；隔离入口 `node .local/close-118/engine-backup-probe-v2.mjs`。

## A04 · P2 · 新八字搭配旧奇门标签可接受错盘或伪称未排盘

- 审计时路径：`src/main/qimen-snapshot.ts` 中旧版分支及未排盘早返，`src/main/store.ts` 的八字／奇门组合校验。
- 触发1：保留八字1.7和确定出生时刻，把奇门替换成1.0标签、`available=false`、空宫位的伪旧快照。
- 触发2：把奇门1.3标签改成1.0，删除后续辅助字段，并改局数、节气和宫干，保留旧版要求的标记形状。
- 复现：两个修改备份均通过形状校验与恢复。前者在已知时刻下显示未排盘；后者原为大雪1局，恢复为伪造冬至9局，库字节发生替换。
- 范围：这是外部修改备份利用版本分派的绕过，不是正常历算算法误排，也不表示所有真实旧盘错误。修复不能用新算法重写已发布旧结果。
- 修复要求：按真实发布过的八字／奇门版本组合分派；现代八字不能任意搭配旧奇门标签。旧版自身仍按对应冻结盘层核对；已知时刻不能借旧标签伪称未排盘。失败时当前库保持原字节。
- 证据：同文件的 `current-fabricated-legacy-unavailable-qimen` 与 `current-fabricated-legacy-wrong-plate`。

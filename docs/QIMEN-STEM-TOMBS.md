# 十干墓支表参考：独立的显式天盘检查

版本：`qimen-go-explicit-stem-tombs/1.0.0`。它是固定开源实现的十干墓支表参考，**不称为完整师承验名体系**。本功能另立结果与资料版本，不覆盖既有三奇入墓规则。

## 固定来源

来源 ID 为 `qimen-go-stem-tombs`，采用 [deminzhang/qimen-go](https://github.com/deminzhang/qimen-go) 固定提交 `4d3f58fa0f401b5b3a337f119138e99e90685dda`，MIT，Copyright (c) 2024 deminzhang。

- `xuan/qimen_defs.go:220–224 QMTomb`：十干所列墓支。
- 同文件 `HideJia`：六旬甲子戊、甲戌己、甲申庚、甲午辛、甲辰壬、甲寅癸是遁甲身份；该身份表没有规定把六仪所在宫另作一个显式甲干的墓库判断。
- `xuan/ganzhi.go:ZhiGong9`：十二支对应洛书宫。墓支转换为宫号使用这张固定表。

原始两个文件及完整MIT许可按原字节保存在 `data/raw/qimen-stem-tombs-go-*`。派生表在 `data/qimen-stem-tombs-table.json`，来源锁在 `data/qimen-stem-tombs-source-lock.json`。每文件SHA及按路径排序的哈希对象摘要均登记；安装运行时固定清单、原表和许可文件逐哈希核验。

原Go仓库没有为 `QMTomb` 的每项注明独立古籍页码或师承。已经确认电子表内容与其实际渲染代码的使用位置，但未取得同师承原典的逐页校勘证据。因此名称采用“qimen-go固定表参考”，不冒称已经核验所有传统流派。

## 运行合同

1. 只检查当前既有转盘的外八宫天盘主干，以及随天芮到实际宫位的寄干，共九个真实乙至癸干。每个干保留实际宫、主干／寄干身份、原墓支和目标宫。
2. 中五说明格不再计一个天盘副本；地盘、暗干、流干均不进入此profile。采用天芮寄干是本产品沿用的盘层输入范围，不声称Go渲染器已独立证明这项寄干算法。
3. 甲虽列于原表，但当前奇仪盘不直接显示甲。其结果必须为 `not-directly-observed`／未直接观测，不能标成未命中，更不能把戊或其他六仪的位置反造为甲的位置。
4. 命中仅表示实际宫与所选固定表目标宫相同，不输出好坏、性格、健康、灾祸或姓名验算结论，不改变命名排序。
5. 出生时刻未知、不提供唯一转盘时，不补造墓支盘面。历史快照保留旧版；新增规则不得回填到生成时没有此项的方案。

## 与其他表的分歧

已有三奇规则固定为乙坤二、丙乾六、丁艮八。此次Go表的**乙为乾六**，因此同一个盘中两个独立profile可能给出不同结构匹配。应并列显示版本和表，不合并成一个“入墓总结果”，也不因为新增十干表而悄悄修改旧乙坤二。

Arc固定项目另转录丁墓乾六的一种读法，本Go表丁丑艮八与其不同；不能因为丙丁都属火就把丁从艮八改去乾六。Go仓库本身的八字 `ZhangSheng12` 长生墓表也与 `QMTomb` 不完全相同，尤其己、庚等。此次只采用 `QMTomb`，不拼入其他表中看起来相近的项目。

这份独立表没有完成甲遁六仪的墓库反解、真假空、四害解除或姓名落宫，亦没有把旧三奇提升为命理吉凶裁决。

## 独立证据

```powershell
node scripts/verify-qimen-stem-tombs.mjs
npx vitest run tests/qimen-stem-tombs-data.test.ts
```

脚本只解析固定外部源码，不导入应用领域函数或日历库。十干墓支／宫有独立人工转录锚点。60项字面查表探针用来核对表成员，**其中甲的字面正例不是当前盘面中的甲观测例**。

盘层例证从此前独立归档的1,080张外部显式局盘数组中选取30张，保留其输入和九宫数组；每个实际可见的乙至癸干都有至少3张命中和3张不命中的独立盘，另覆盖阴遁、寄干和中宫说明副本。甲在这些真实转盘例中均必须保留未直接观测。完整1,080盘统计和外部夹具文件哈希同时记录于 `tests/fixtures/qimen-stem-tombs-examples.json`，不能反向调用应用引擎生成期望值。

这些证据验证所选表的成员查找、宫号映射和软件盘层范围，不证明原典流派一致、墓库能影响命运或任意姓名已经验局通过。

# 1.0.2 审计修复对应表

以下对照原审计的14项问题，记录实现及其回归证据。原客户库未用于测试；单元/集成测试使用临时目录，界面测试使用独立 `.local/audit-ui` 工作区和本机固定响应AI。

| 原问题 | 修复与证据 |
| --- | --- |
| 多实例覆盖客户库 | Electron单实例；Store互斥、磁盘哈希与失败回滚；storage-regression覆盖第二写入者拒绝及现库不变 |
| 密钥不绑定接口 | EndpointSecretStorage存储加密的版本/规范化端点/密钥；换地址、恢复备份、未保存新地址测试连接和配置失败回滚均有集成用例 |
| 多音字读音义项混合 | MOE按heteronym保留原义；逐字逐读音回对原始快照，朝/长/乐专门回归；结构化polyphonic参与评分 |
| 切客户串偏好 | 每个profile保存自己的namingPreferences；旧档使用本客户最新方案，无记录用默认；UI实测A指定“知”而B为空 |
| 慢AI覆盖新输入 | 请求ticket包含客户和编辑版本；旧回包仅保留后台方案；10秒慢AI实测期间新建王姓、妈妈姓名及客户称呼未被覆盖 |
| 改约束后交付旧结果 | 输入草稿与生成快照对比；结果过期醒目提示，禁用审阅/交付；UI实测禁用“知”后PDF按钮禁用 |
| 报告预览与PDF不同 | 共用getReportCandidates，预览完整名单；UI实测仅收藏第8名时预览只显示该名，集成测试断言PDF HTML相同名单 |
| 换一组名单不变 | seed参与候选择取，服务排除同客户同约束历史名字；14种seed回归，UI两批12名无交集 |
| 不适用字典首义作祝愿 | 字典原文保留，命名义/组合寓意使用受控编辑数据；安然/知微回归不含燃烧/隐藏等误用 |
| 古籍字面共现当出处 | 仅通过姓名、读音、原文定位及语境审定的规则可声明出处；被弃、不宁、予和错误例不再取用 |
| AI事实断言绕过 | 模型仅选名字、受控主题和引用ID；本地重建解释，不发布自由prose；原错误五行与虚构篇章原样作为回归输入被拒绝 |
| AI检索忽略文化偏好 | 文化来源优先、审定用字保留、多源参考配额；真实五行偏木160字初筛链路仍保留周易和审定引文 |
| 父母避讳漏简繁 | 父母/手动禁用/长辈避讳共用Unicode简繁异体扩展；“林志遠”阻止“远宁”，AI用字池与返回校验一致 |
| 备份恢复校验不全 | PRAGMA完整性、标准表主键/列、完整嵌套记录及历史关系校验；无主键/坏字段/孤立历史备份拒绝且原库不变 |

审阅历史新增界面查看、差异比较和应用内确认恢复，恢复本身保留当前版本作为历史。另修复后台刷新覆盖设置草稿、八字选择回显与审阅保存期间输入覆盖问题。

传统扩展按用户选择另行分阶段规划，见 `TRADITIONAL-EXPANSION.md`，不扩大本轮已经验证的算法范围。真实第三方AI和另一台干净Windows仍按原有外部条件验收，不能以本机固定响应或移除开发PATH代替。

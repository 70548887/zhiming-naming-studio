# 任注后续判断的证据求值合同

阶段记录：本文件前述修复发生在任注1.3接入之前。后续1.0.26候选已将这里的 `sufficient-only` 求值用于[木局旺势与辰生助的限定能力](REN-CAPACITIES-SOURCES.md)，未把它升级为完整有效根气、净作用或判格；旧版本冻结要求继续保留。

本轮修复的是推理依赖的执行层，尚未新增任注1.3取法，也未将现有1.2的有效作用改成已成立。已交付1.0.25安装包保留原字节；历史1.0、1.1、1.2计算器继续使用冻结实现。

当前开发入口 `src/domain/ditian-ren.ts` 显式导出 `src/domain/ren-dependencies.ts` 的新求值器。新判断只能在来源、条件范围和独立正反例齐备后调用它；执行器本身不提供旺衰、冲克力量或姓名验局的传统规则。

## 修复的问题

旧递归求值器遇到 `A = B 且 F`、`B = A`、独立证据 `F不成立` 时，可能因输入顺序不同而将B输出为待核或不成立。新求值器将独立反证传播到整个依赖环，A、B均不成立，同时保留涉及循环的标记。

旧历史计算器不替换为新求值器。测试用实际1.0.25安装版SQLite的五份当前方案和一份历史方案冻结完整分析，并记录原安装包和读取前后数据库摘要；旧期望不是由新计算器生成。

## 证据与规则方向

每个命题分别累积支持和反对证据：都没有为 `unknown`，只有支持为 `met`，只有反对为 `not-met`，两者都有为 `conflict`。未知不等于不存在，冲突不通过投票消除，也不会使无关命题成立。

`observed` 是该命题的独立证据。不能把依赖命题自己的结论、人工猜测或原书某个相似盘的结论填成独立观测。来源、具体字位和观察范围由后续领域规则保存，执行器只接受结构化状态。

| 模式 | 所列条件齐备 | 必要前提被否定或阻断已成立 |
| --- | --- | --- |
| `necessary-only` | 不据此证明结论 | 可反对本条必要路径 |
| `sufficient-only` | 可支持结论 | 不能由本充分路径失败否定结论 |
| `complete-contract` | 可支持结论 | 可反对结论 |

默认的 `complete-contract` 只适用于已明确采纳、同时具有必要和充分语义的闭合合同。**任注1.2现有必要条件不能直接套用此默认模式。** 不能因为所有已实现的条件都通过，就把尚未定义的力量、到达或救应前提视作通过。

每项规则的条件为所有 `premises` 成立，且所有 `inhibitors` 有反证。多个替代作用路径须分别建命题，再按有来源的组合规则汇总；未证明路径已经穷尽时，不能以全部已知路径失败推断全盘无救。

空条件且无独立证据的命题保持未知。无种子的正向环、负向环及自环均不自证；独立证据可以进入循环传播，循环标记仍保留。若独立正反证据与规则产生冲突，结果保留冲突。

## 执行边界

求值先检查普通JSON结构、字段描述符和资源上限，再做规范化。最多4096个命题、65536个引用；稀疏数组、访问器、隐藏字段、自定义原型、重复编号、重复引用和缺失引用拒绝。超大的引用数组在遍历或序列化前拒绝，不执行其访问器。

环与可达性检查使用迭代算法，证据传播只增加支持或反对信息，结果不依赖输入顺序。合法编号如 `__proto__`、`constructor`、`toString` 按实际命题处理，不从对象原型取得伪结果。

## 仍须闭合的领域条件

原文中的“旺提纲”“有力”“无金”“无水”不能先换成月份相等或明藏计数，再称已经实现完整有效作用。原书反例与采用边界见 [有效作用研究](REN-EFFECT-RESEARCH.md)；奇门姓名映射及有效解除的缺环见 [奇门姓名验局研究](QIMEN-NAME-RESEARCH.md)。

下一步应为具体作用逐一提供独立的能力、到达、靶标承受、阻断与救应判据，并以原书正例、反例和边界例检验。只有这些领域条件闭合，才把新求值器用于新取法和保存快照；当前不改喜用候选、姓名评分或旧方案。

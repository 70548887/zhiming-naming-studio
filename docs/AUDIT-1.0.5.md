# 1.0.5 完善度审计

审计日期：2026-10-18。对象：知名起名工作室 1.0.5 的现有功能、UI 规划、数据保存与发布验收。本轮没有修改应用代码，也没有修改实际客户库。浏览器使用 5174 的隔离样例；服务复现使用独立临时库和本地固定响应，不调用真实 AI 服务。

本轮确认 **5 项 P2 实现缺陷**、**2 项边界加固项**。它们与规划中尚未实现的功能分开统计。建议先处理设置草稿与保存/恢复的一致性，再开发新的界面和术数功能。

## 优先修复的实现问题

### A01｜设置保存的迟到响应会覆盖新输入（P2）

- 位置：`src/renderer/main.tsx:47`、`:148`。
- 触发：点击保存设置或品牌，在请求完成前继续修改工作室名称、联系方式等字段。
- 结果：输入控件仍可编辑，但返回后 `applySettings(saved)` 整份替换当前草稿，新输入被恢复为提交时的旧值。
- 证据：直接执行当前源码处理器的隔离事件测试得到 `beforeReturn=保存期间继续输入的新名称`、`afterReturn=原工作室`，`inputDisabled=false`。这项是事件处理器级复现，不是浏览器慢网端到端测试。
- 完成标准：保存仅更新已提交版本的基线；请求期间的新输入继续保留并标记未保存，或明确禁用相关输入。保存后继续编辑、切换面板也要覆盖。

### A02｜“保存品牌”会连带提交尚未保存的 AI 设置（P2）

- 位置：`src/renderer/main.tsx:148`；`src/main/service.ts:97` 起的设置与凭证更新逻辑。
- 触发：在 AI 区域修改接口地址或超时等字段，转到品牌区域点击“保存品牌”。该按钮传递整份设置，却不传当前新输入的 API 密钥。
- 结果：品牌操作会受 AI 草稿校验影响；若提交了新接口，服务还会清除原接口的已存密钥并关闭 AI，新输入的密钥仍只留在输入框中。
- 浏览器实测：把 AI 超时改为 0，填写临时品牌名，点击“保存品牌”，实际返回“超时需为5–120秒”，品牌保存被另一个面板阻断。测试输入已还原。
- 凭证影响：由当前源码事件处理器和服务地址绑定逻辑确认；未操作真实密钥。
- 完成标准：品牌与 AI 的提交范围分开；品牌按钮不得修改接口、模型、密钥与 AI 开关。或者统一为明确的“保存全部设置”，并一次提交一致的凭证草稿。

### A03｜读取品牌图片时会回退同期编辑内容（P2）

- 位置：`src/renderer/main.tsx:148` 的 `FileReader.onload`。
- 触发：选择品牌图片，在读图回调前修改报告联系方式等字段。
- 结果：回调通过闭包中的旧 `settings` 整份写回，覆盖读图期间的其他输入。
- 证据：执行当前源码上传处理器并延迟 `onload`，新联系方式在回调后变回旧值。未执行浏览器文件选择器端到端测试。
- 完成标准：图片读取完成后只更新 `logoDataUrl`，基于最新状态合并；覆盖连续选两张图和读取失败情形。

### A04｜方案写入和备份恢复使用不同强度的校验（P2，服务边界）

- 位置：`src/main/service.ts:56` 起；`src/main/store.ts:91`；恢复校验位于 `store.ts:112`、`:119`。
- 触发：通过现有服务接口保存重复候选 ID，或对象类型的方案总审阅意见。
- 结果：保存成功，但 `restore(backupBytes())` 拒绝刚由自己导出的备份。恢复正常历史后，坏快照还会被保存到 revisions，备份仍然无法恢复。
- 证据：真实隔离 SQLite 与 `StudioService` 调用，无需手改客户数据库。正常 GUI 的文本框和候选列表不会构造上述异常字段，不能把这一项描述为普通用户已遇到的备份损坏。
- 完成标准：方案保存、历史归档、恢复和导入使用同一完整规范；拒绝无效写入时磁盘与历史均不改变；加入“保存→编辑→历史恢复→备份→恢复”的往返测试。

### A05｜知识包允许冲突来源 ID，出处元数据会被覆盖（P2）

- 位置：`src/main/store.ts:65`–`:68`；`src/main/service.ts:18`。
- 触发：导入含两条相同来源 ID、不同名称或 URL 的数据包。
- 结果：导入通过，随后 bootstrap 的 Map 保留最后一条来源；原有同 ID 的引文可能显示冲突的来源信息。
- 证据：隔离数据包含两条 `zhouyi` 来源，`installPack` 成功，内存数据中保留重复项。正常“导入数据包”可到达此路径，但需要存在问题的数据包；随 1.0.5 发布的原始包未发现此冲突。
- 完成标准：校验 sources、citations、knowledge 的 ID 唯一性和引用关系；错误包不得替换当前包；明确“知识数据包”不包含随应用独立发布的数理、奇门规则更新。

## 需要加固的故障与并发边界

### B01｜生成客户与方案不是一次事务

`src/main/service.ts:54` 分别保存客户和方案。故障注入第二次保存失败后，调用报错，但客户资料已经变更，方案不存在。建议合并事务或定义并验证部分成功后的恢复策略。这是故障注入结果，不代表当前机器出现过磁盘故障。

### B02｜正在生成的请求可能重新创建已删除客户

本地延迟 HTTP 复现：生成请求未结束时删除客户，客户数变为 0；请求完成并回退本地候选后，客户数恢复为 1、方案数为 1。位置为 `src/main/service.ts:48`、`:54`。同一正常窗口的 busy 锁阻止并行删除，因此主要属于多客户端、过期请求或服务接口并发的边界。建议加入请求取消、删除版本或提交前存在性检查。

## 已规划但仍未实现

这些属于后续开发，不计入上面 5 项缺陷。

- **方案管理**：按客户、姓氏、时间和收藏筛选；方案批次辨识、排序。
- **候选与比较**：展示排序选项；完善比较上限、移除反馈及窄窗口长文阅读。
- **报告交付**：集中导出确认，汇总方案、名字数、收藏范围和意见保存状态；清楚区分导出取消、失败与成功。
- **使用体验**：快捷键说明、首次使用引导、舒适/紧凑密度、字号偏好、术语就地解释。
- **数据维护**：导入前变更摘要、规则包范围说明、备份与回退状态、校验与版本集中展示。
- **奇门扩展**：门迫、击刑、入墓、伏吟/反吟；姓名落宫仍需明确取法和独立例盘。
- **八字扩展**：月令司权、扶抑/调候分别输出、从格与合化候选、可选真太阳时。

具体验收口径沿用 `UI-DETAILS-PLAN.md` 和 `TRADITIONAL-EXPANSION.md`，不把已实现的康熙五格、时旬空、时驿马重复列为未完成。

## 仍缺少的验收与发布工作

- **交互自动化不足**：Modal 的两项自动测试只检查静态 HTML 标记，不检查真实焦点围栏、嵌套 Escape 或输入法。上一轮的 10 项针对性检查中，6 项运行 helper，4 项匹配源码；不能等同于 10 项完整交互测试。
- **Windows 原生关闭提示**：需要分别实操“继续编辑”和“放弃修改并关闭”，核对草稿及关闭结果。
- **外部环境**：用户真实 AI 服务联调、另一台干净 Windows 仍未执行；跨机验收按此前约定后续安排。
- **代码签名**：本轮用 `Get-AuthenticodeSignature` 检查，安装包与安装后的主程序均为 `NotSigned`。如需正式对外发行，应完成发布者签名与相应验收，构建日志中的 signing 字样不能当作已签名证据。
- **正式验证文档滞后**：`docs/VERIFICATION.md` 缺少 1.0.4/1.0.5 的版本分节；相关实测证据目前主要保存在 `.local`，需要整理进正式发布记录。

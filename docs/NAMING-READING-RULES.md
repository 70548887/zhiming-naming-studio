# 命名释义与读音适用范围

1.0.31 的命名整理规则为 `naming-editorial-4.0.0`。本次修复导入字库切换到其他合法读音后，仍沿用默认读音的项目寓意和语义加分的问题。例如“乐”改读 `yuè` 时，原字典音乐义仍保留，不再使用“愿孩子常怀喜悦”的乐安组合解释。

## 数据与适用范围

`data/naming-editorial-v4.json` 独立登记已发布 1.0.30 中 779 字的默认读音、读音来源及原字典字形，并为项目字符意象、组合寓意和自然词表建立适用绑定。它表示原项目解释在哪个读音范围内可用，不表示 779 字的命名义全部经过人工审定。缺字或缺少可绑定读音的旧词条保留待核，运行时不采用当前导入包临时补审。

`data/naming-editorial.json` 的 3.0 原件和既有 40 条／44 名出处规则保留原字节。本轮不增加出处数量，也不把原典全文的字面共现当作名字出处。出处仍须同时满足完整条目身份、原文摘录、语境与登记读音。

项目释义、现代组合、自然表达词表、寓意主题和行业意象的语义信用均核适用读音。实际字典释义仍可独立匹配文字主题；用户明确的偏好以及纯字形、笔画、读写简洁度不被当作古典字义审核。失配读音保留对应字典原文，并提示命名适用义待审。该机制不改写原字库事实、八字、奇门、康熙五格或粤语方法。

## 新旧方案

新生成方案同时保存 `namingRules.version`、本次字库 `dataVersion` 和固定来源 `naming-editorial-readings-v4-fixed`。只带版本、不带来源，或数据版本、来源内容不一致时拒绝保存和恢复；知识包不允许占用固定规则来源。

未记录独立命名规则的历史方案保留原解释、评分、字库、来源和历史；不猜测它使用 2.0 还是 3.0，也不按当前 4.0 重算。审阅、收藏、备份恢复和 PDF 仍使用保存快照。界面与报告说明该边界；重新生成才采用当前规则。

## 仍需补充

新读音的命名适用义需分别审阅。新增古籍出处、现代组合、其他方言与连读音变也需独立证据，不能由当前默认读音或模型解释自动推定。最终测试、安装和 PDF 验收以 1.0.31 安装包旁的实际验证记录为准。

字库及候选详情把原字库备注折叠保存，并标明可能未随所选读音调整；展开可查原文，方案的当前读写提醒单独显示。此显示调整另有3项新增界面测试及实际可见文字验收。
